# 로컬 카탈로그 갱신

운영자가 공개 원본의 권리와 revision을 확인하고 로컬 파일로 수신한다. 원격 동기화 설계에서는 발행자가 제공한 release ID, 출처, 레코드 수와 SHA-256 manifest를 검증한 파일만 staging에 넘긴다. 다운로드 중단이나 checksum 불일치 시 해당 파일을 격리하고 다음 동기화에서 다시 받는다. 네트워크 수신 어댑터는 후속 구현 범위다.

scripts/import_catalog.py의 stage → validate → publish 순서로 반영한다. 실패한 staging은 추천 경로에 노출되지 않는다. publish가 성공하면 활성 포인터와 cache_version이 한 트랜잭션에서 변경된다. 이전 published release는 보관한다. rollback --source SOURCE --release UUID로 이전 버전을 다시 활성화한다.

검토자는 규격·원재료·가공 상태와 g 기준 영양을 대조하고 catalog_ingredient_links에 로컬 재료 ID, 해당 release UUID, 공식 food_id와 reviewed_at을 기록한다. 새 release에서도 검토를 반복한다. 이름 일치만으로 자동 연결하지 않는다.

ThinQ 데모는 VirtualFridge.sync로 연결 성공·중단 및 마지막 동기화 버전을 표시한다. 실제 기기 계정은 필요하지 않다. Supabase 운영 경계는 validate_metric의 일별 집계 필드만 허용한다.
