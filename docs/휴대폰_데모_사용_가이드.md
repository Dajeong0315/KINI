# 휴대폰 데모 사용 가이드

## 먼저 알아둘 점

현재 UX/UI 화면과 가족 맞춤 추천 백엔드는 **일부만 연결**되어 있다.

- 실제 연결됨: 재고 조회, 개별 재료 영양 조회, 조리 중 일반 질문(`/api/chat`)
- 아직 화면 연결 전: 가족 참여자 선택, 추천 3개, 추천 근거, 조리 재료 변경, 식사 기록 저장, 개인화 피드백

따라서 휴대폰에서는 화면 흐름과 음성·조리 질문 경험을 확인할 수 있고, 가족 맞춤 추천·조리 세션·기록은 API로 별도 검증할 수 있다. 화면의 메뉴명·영양 수치·프로필은 현재 일부 정적 데모 표현이다. 실제 알레르기나 건강 판단에 사용하면 안 된다.

## 1. 휴대폰으로 화면 열기

1. PC와 휴대폰을 같은 Wi-Fi에 연결한다.
2. PC 터미널에서 프로젝트 폴더로 이동한다.
3. 개발용으로만 다음처럼 실행한다.

```powershell
$env:APP_HOST = "0.0.0.0"
python -m app.main
```

4. PC에서 `ipconfig`를 실행해 현재 Wi-Fi의 IPv4 주소를 확인한다. 예: `192.168.0.12`
5. 휴대폰 브라우저에서 `http://192.168.0.12:5000`을 연다.
6. 브라우저 메뉴에서 홈 화면에 추가하면 앱처럼 실행할 수 있다.

`0.0.0.0`은 같은 Wi-Fi 기기에서 접속하도록 여는 개발용 설정이다. 외부 인터넷에 공개하지 말고, 실제 건강·알레르기 정보는 입력하지 않는다.

## 2. 화면에서 확인할 수 있는 데모 경로

### A. 오늘 저녁 메뉴를 고르는 흐름

1. **오늘** 화면에서 함께 먹을 가족 구성원을 선택한다.
2. `추천 보기` 또는 하단 `추천` 탭을 누른다.
3. 추천 메뉴 3개와 추천 근거 화면을 확인한다.
4. 한 메뉴를 선택하고 `레시피 보기` → `조리 시작`으로 이동한다.

확인할 점:

- 가족 선택 UX가 직관적인지
- 추천 근거가 이해하기 쉬운지
- `데모 데이터`, `확인 필요` 같은 안전 안내를 어디에 보여줄지

현재 제한: 이 화면의 참여자 선택과 추천 카드는 API 결과를 아직 반영하지 않는다.

### B. 조리 중 질문 흐름

1. `조리 시작` 화면으로 이동한다.
2. 아래 입력창에 예를 들어 `두부는 씻어서 넣어야 해?` 또는 `국물이 짜요`라고 입력한다.
3. `보내기`를 누른다.

이 경로는 현재 `/api/chat`을 호출한다. 일반 조리 질문의 응답 경험은 확인할 수 있지만, 조리 세션의 재료 중량·영양 재계산과는 아직 연결되지 않았다.

### C. 냉장고 재고 확인 흐름

1. 하단 `냉장고` 탭을 누른다.
2. 재료 목록과 우선 사용 표시를 확인한다.
3. 재료 오른쪽 화살표를 눌러 영양성분 정보를 확인한다.
4. `재고 새로고침`을 눌러 실제 `/api/inventory` 응답이 다시 보이는지 확인한다.

현재 `+ 재료 등록`은 안내 메시지이며, 정규화된 재고 등록 API 화면은 아직 연결 전이다.

## 3. 백엔드 기능을 직접 검증하는 추천 시나리오

화면이 연결되기 전에는 PC의 PowerShell 또는 API 도구에서 아래 순서로 확인한다. 기본 주소는 `http://127.0.0.1:5000`이다.

### 시나리오 1 — 엄마와 할머니 저염 저녁 추천

```powershell
$base = "http://127.0.0.1:5000"

Invoke-RestMethod "$base/api/recommendations" -Method Post -ContentType "application/json" -Body '{
  "household_id": 1,
  "participant_ids": [2, 4],
  "meal_type": "dinner",
  "cook_time_limit_minutes": 30,
  "purchase_allowed": false
}'
```

확인할 결과:

- `recommendations`에 최대 3개 후보가 있는지
- `excluded_candidates`에 제외 사유가 있는지
- `data_quality`, `warnings`, `requires_confirmation`을 함께 읽는지
- 후보가 없을 때 `status: no_safe_recommendation`을 억지 추천보다 우선하는지

구성원 ID는 데모 DB 기준이므로, 먼저 아래 요청으로 확인할 수 있다.

```powershell
Invoke-RestMethod "$base/api/households/demo"
```

### 시나리오 2 — 재고 재료를 안전하게 등록하기

먼저 입력을 정규화한다.

```powershell
Invoke-RestMethod "$base/api/inventory/normalize" -Method Post -ContentType "application/json" -Body '{
  "name": "당근 1개",
  "quantity": 1,
  "unit": "개"
}'
```

`개`는 실제 중량 근거가 없으므로 `requires_confirmation: true`와 `quantity_g: null`이 나오는 것이 정상이다. 실제 무게를 확인한 뒤 g 단위로 저장한다.

```powershell
Invoke-RestMethod "$base/api/inventory/items" -Method Post -ContentType "application/json" -Body '{
  "household_id": 1,
  "ingredient_id": 3,
  "name": "당근",
  "quantity": 200,
  "unit": "g"
}'
```

### 시나리오 3 — 추천 메뉴를 조리하고 실제 사용량 반영하기

1. 추천 응답의 `request_id`와 원하는 `recipe_id`를 기록한다.
2. 조리 세션을 만든다.
3. 재료를 바꾸면 결과의 `requires_confirmation`, 제한 조건, 영양 정보를 확인한다.
4. 문제가 없을 때만 완료 요청으로 식사 기록을 남긴다.

이 단계의 상세 요청 형식은 `README.md`의 조리 세션 예시를 따른다.

## 4. 현재 데모에서 받아야 할 사용자 피드백

가족 또는 팀원에게는 다음 네 가지만 먼저 물어보면 된다.

1. 가족 구성원을 고르는 과정이 자연스러운가?
2. 추천 근거에서 가장 먼저 보고 싶은 정보는 무엇인가? 재고, 영양, 시간, 알레르기, 취향 중 무엇인가?
3. `확인 필요` 안내가 이해되는가? 어떤 표현이 부담스럽거나 부족한가?
4. 조리 중 재료를 줄이거나 빼고 싶을 때, 어느 화면에서 수정하고 싶을까?

## 5. 화면 연결의 다음 우선순위

1. 가족 구성원 선택 UI를 `/api/households/demo`, `/api/members`와 연결
2. 메뉴 추천 화면을 `/api/recommendations` 결과로 렌더링
3. `data_quality`, `warnings`, `excluded_candidates`를 화면에 표시
4. 선택 메뉴를 `/api/cooking-sessions`에 연결
5. 조리 변경·질문·완료를 조리 세션 API에 연결
6. 식사 기록과 추천 피드백을 개인화 메모리에 연결

이 순서가 완료되면 현재 UX/UI의 화면 흐름과 안전 규칙·개인화·기록 기능이 하나의 실제 데모 경로가 된다.
