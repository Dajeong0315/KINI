검증한 불변 조건:

- A 확정 전 미차감, A 동일 이벤트 중복 확정 시 1회 차감, B는 재고를 변경하지 않음.
- 동시 확정·동시 B 완료·같은 출고 이벤트를 다른 조리에서 재사용하는 경쟁 방지.
- 재고 부족, 다른 가구·조회 전용 계정·무인증·만료 세션, 허용되지 않은 재료·섭취량 거절.
- 식사·개인 항목·영양·개인화 증거·완료 갱신 각 지점의 합성 DB 실패 시 B 쓰기 전체 rollback. 이미 확정된 A 출고는 보존하고 복구 후 동일 세션 완료 가능.
- 저장된 개인별 실제 섭취량·영양 스냅샷을 이력·상세·리포트에서 재조회. 날짜 경계·누락 영양·가구 격리·읽기 전용 보장.

중간 실행 한 번은 이미 사용한 테스트 DB를 재사용해 fixture 고정 `data_sources.id=90`과 충돌했다(1 failed / 62 passed). 제품 코드 실패가 아니며, 별도 새 DB에 migration 후 같은 관련 63개 전체를 다시 통과한 결과가 위 표다. 운영 DB에 TRUNCATE나 오류 트리거를 실행하지 않았다.

[실제 휴대폰 확인 절차](5단계_실제휴대폰_확인절차_2026-11-27.md)의 로그인→가족 선택→입고→추천→조리 변경→A 출고→B 완료·개인 섭취→재로그인 이력·리포트를 실제 휴대폰에서 확인해야 한다. PC Chrome의 390×844는 이 조건을 대신하지 않는다.
