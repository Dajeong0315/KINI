- B runtime에 같은 출처 화면과 기존 가족·재고·이력·리포트 API를 노출했다. 병렬 읽기 요청은 허용하고 추천 추론 admission 제한은 유지했다.
- 조리 시작의 동일 트랜잭션 안에서 반복되던 영양·안전 검증을 재사용했다. 요청 간 캐시나 안전 검증 생략을 추가하지 않았다. 실제 최초 조리 시작의 15초 제한 초과를 수정한 것이다.

- 식후 평가 저장은 기존처럼 비활성 상태다. 6단계 기획을 확정한 것으로 취급하지 않는다.

운영 DB에는 정상적인 합성 시연 계정 흐름만 실행했다. 실패 주입·재고 부족·타 가구·만료 등의 오류 테스트는 별도 테스트 DB에서 수행했다.

서버 loopback 경로의 정상 흐름 1회 측정: 추천 11.756초, 식사 세션 4.017초, 조리 시작 9.740초, B 저장 14.061초, 이력 3.206초, 상세 3.208초, 리포트 3.338초. 동시 부하·백분위·실제 모델 성능 수치가 아니다. 서버 예산 15초와 브라우저 20초는 유지했다. 저장 시간이 서버 예산에 가까우므로 4단계에서 추가 측정이 필요하다.

## 남은 실제 휴대폰 확인

Tailscale 연결 휴대폰에서 `/mobile` 접속 → 시연 계정 로그인 → 영양 관리의 0.5인분 저장 기록·기록 상세·영양 확인 → 새로고침·재로그인 후 같은 기록 확인. 실패한 경우 기종·브라우저·실패 단계와 화면의 오류 문구만 전달받는다. 비밀번호나 세션 토큰은 요청하지 않는다.

시연 자격은 저장소 밖의 접근 제한 파일에 보관했고 문서·Git에 포함하지 않았다. 실제 휴대폰 확인 결과를 받은 뒤 이 위치부터 3단계 완료 판정을 재개한다.
