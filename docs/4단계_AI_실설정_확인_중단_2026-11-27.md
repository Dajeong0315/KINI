## 완료한 확인

- 3단계 구현·서버 반영, 별도 DB 오류 테스트, 실제 Supabase 정상 저장·조회, 배포 HTTPS의 PC Chrome 390×844 재로그인·상세·리포트 검증은 완료했다. 실제 휴대폰 확인은 사용자 답변 대기다. [3단계 기록](3단계_화면_API_연결검증_2026-11-27.md) 참조.
- 서버의 실제 환경 파일에서 허용한 비밀 아닌 설정과 비밀의 존재 여부만 조회했다. 비밀번호·키·세션 원문은 출력하지 않았다. 원본 프로젝트 `.env`, 현재 프로세스 환경에도 동일한 설정의 존재 여부를 확인했다.
- 서버 `KINI_B_AI_MODE=rules-only`, `KINI_B_STORAGE=postgres`, 요청 예산 15초. `OPENAI_API_KEY` 미설정, `OPENAI_RECOMMENDATION_MODEL` 미설정, `KINI_B_EXTERNAL_APPROVED` 미설정. 원본 `.env`와 현재 프로세스에도 세 항목 모두 미설정이다. 다른 임의 자격증명 저장소를 탐색하거나 타 서비스 키를 가져오지 않았다.
- 기존 `real` 호출 경로: `app/b_runtime.py` → `PrivacyGateway`의 `OllamaPrivacyInspector` → `HttpOpenAIRecommendationClient` → `https://api.openai.com/v1/responses`. 내부 모델은 전송 전 개인정보 검사, 외부 모델은 검증된 후보의 설명 생성이다. 실제 모드에는 fake 자동 전환이 없다.
- `rules-only`는 두 모델을 호출하지 않는 명시적 규칙 추천이다. `synthetic-fake`는 검사·외부 응답 모두 test double, `synthetic-ollama`는 실제 검사 + fake 외부 설명이다. 뒤의 두 모드는 별도 합성 SQLite에서만 허용된다. 실제 PostgreSQL에서 synthetic 모드를 활성화하지 않았다.
- 실제 모드 시작 조건은 승인 flag, OpenAI 키, 모델 설정을 모두 요구한다. 이를 우회하거나 임의로 승인 flag를 설정하지 않았다.

## 확인된 중단 조건

사용자 지시의 4단계 중단 조건인 **모델 사용 결정, 계정 권한 또는 비용 승인 필요**에 해당한다.
실제 모델·OpenAI 프로젝트 접근·비용 승인 근거가 확보되지 않아 정상·지연·실패 측정과 timeout/요청 예산 조정을 완료할 수 없다. 설치된 Ollama만으로 현재 real 모드의 외부 설명 계약까지 충족했다고 표시하지 않는다.

## 요청 대상과 전달문

요청 대상: 사용자 또는 사용할 OpenAI 프로젝트의 계정·비용 권한 소유자. 특정 팀원을 계정 소유자로 추정하지 않는다.

> KINI 4단계 실제 AI 검증을 위해 현재 코드의 ‘Ollama 개인정보 검사 → OpenAI 추천 설명’ 경로를 사용할지 결정해 주세요. 사용할 OpenAI 프로젝트·모델, 허용 시험 호출 수 또는 비용 상한을 알려주시고, 해당 프로젝트의 API 키는 채팅 대신 서버의 보호된 환경 파일에 직접 등록해 주세요. 등록 방법이 필요하면 비밀값을 노출하지 않는 절차를 준비하겠습니다. 현재 서버에는 키·모델·계정/비용 승인 설정이 없습니다. OpenAI 없이 Ollama만 사용할 계획이라면 그 방향을 결정해 주세요.

실제 계정 접근과 비용 근거를 확인하기 전 `KINI_B_EXTERNAL_APPROVED=1`을 완료 증거로 임의 설정하지 않는다. 비밀번호·API 키·결제 정보를 채팅으로 요구하지 않는다. 팀원에게 메시지는 보내지 않았다.

## 재개 위치

1. 받은 모델 사용 결정과 승인 범위를 확인하고 보호된 서버 설정의 존재·실제 프로젝트 접근을 검증한다.
2. 별도 테스트 환경에서 실제 Ollama 정상·지연·실패 동작, 승인된 최소 OpenAI 요청, 메모리와 응답 시간을 측정한다. 운영 DB에는 파괴적·실패 주입 테스트를 실행하지 않는다.
3. 측정 결과에 따라 요청 예산·브라우저 timeout·추론 동시성 제한을 조정하고 관련 검증 후 배포한다.
4. 3단계 실제 휴대폰 확인을 받으며, 5단계 전체 흐름과 오류·재시도·가구 격리를 별도 합성 DB 및 실제 서버·휴대폰에서 검증한다. 둘 다 통과한 뒤 첫 배포 가능한 기능 묶음으로 보고한다.

이번 확인으로 서버 환경·DB·서비스 실행 방식·Git 커밋/푸시를 변경하지 않았다. 현재 서비스는 검증된 3단계 release를 계속 사용한다.
