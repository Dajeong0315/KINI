# 4단계 — 사용자 결정에 따른 AI 비활성 경로 검증

결정 수신·작업·검증일: 2026-11-27 KST.

**이번 결정 범위의 설정 확인 완료.** 기존 ‘실제 AI 정상·지연·실패 측정’은 사용자가 보조 검사와 OpenAI 설명 호출을 0회로 결정하여 이번 범위에서 제외했다. 실제 AI 성능 검증을 완료했다고 표시하지 않는다. [이전 중단 기록](4단계_AI_실설정_확인_중단_2026-11-27.md)의 계정·비용 의존성은 비활성 결정으로 해소됐다. API 키 발급·등록은 필요하지 않다.

## 코드·실제 서버 확인

- 사용자가 원본 작업 폴더에 작성한 [운영 결정](AI_설명_경로_운영결정_2026-11-27.md)을 별도 worktree로 가져왔다. 원본 `.env.example`, README와 기타 미커밋 변경은 보존했다.
- 별도 worktree `.env.example`에 `KINI_USE_OPENAI=0`, 미사용 키·모델 항목, 보조 검사/OpenAI 시험 0회·USD 0을 반영했다. 비밀값은 포함하지 않았다.
- `ssh kini-b`의 비대화형 인증 성공을 직접 확인했다. 기존 키를 지정하는 SSH 별칭이 정상 동작한다. SSH 설정·개인키를 변경하거나 복사하지 않았다.
- 서버 `/etc/kini-b/runtime.env`: `KINI_B_AI_MODE=rules-only`, `KINI_USE_OPENAI=0`, `OPENAI_RECOMMENDATION_MODEL` 미설정, OpenAI 키 없음. root:kini-b 0640 설정 파일을 사용한다. 설정값을 바꾸거나 키를 등록하지 않았다.
- 기존 `rules-only` 분기에서 추천·안전 계산 결과에 고정 설명과 `ai_status=disabled`를 붙인다. Ollama 보조 검사·실제 OpenAI·fake 설명 클라이언트를 호출하지 않는다. 실제 AI 오류를 이 경로로 자동 대체하는 구조가 아니다.
- `tests/test_b_runtime.py::test_explicit_rules_mode_uses_no_models_and_is_labelled`가 세 클라이언트에 호출 시 실패하는 spy를 연결하고 규칙 추천·라벨을 검증한다. API에 원문·알 수 없는 필드를 넣는 경우의 기존 차단도 유지한다.
- 실제 배포에는 요청 해석·일반 채팅 경로를 노출하지 않는다. 비활성 설명 경로의 시험 호출은 0회이며, 자동 재시도도 없다.

## 모델 불일치와 범위

> 후속 사용자 결정: 로컬 기본 모델도 `qwen2.5:3b-instruct-q4_K_M`으로 변경했다.
> 원본과 통합 worktree의 기본값·예제·README·테스트를 맞췄고 원본 `.env`의 모델 항목만 바꿨다.
> 로컬 `/api/tags`에 해당 모델이 설치되어 있음을 확인했다. 모델 관련 테스트 13개가 통과했다.
> 실제 추론·보조 검사·OpenAI 호출은 수행하지 않았다. 아래 qwen3.5 내용은 후속 결정 전 확인 이력이다.

원본/별도 worktree의 기본 요청 해석·채팅 모델 설정은 `qwen3.5:4b-q4_K_M`이다. **실제 B 서버에는 `qwen2.5:3b-instruct-q4_K_M`만 설치되어 있고 환경도 그 이름을 가리킨다.** Ollama `/api/ps`는 models=[]였다. 로컬 설정을 서버 설치 증거로 사용하지 않는다.

이번 B 경로에서는 모델이 사용되지 않으므로 다운로드·교체·추론을 하지 않았다. 기존 로컬 qwen3.5 설정은 보존했다. 향후 실제 요청 해석·채팅을 B 서버에 열 때 모델 설치·실행·성능을 따로 검증해야 한다.

## 검증

- 로컬 기존 Python 환경에서 `test_ai_privacy_chain.py`, `test_recommendation_ollama_settings.py`, `test_ollama_model.py`: **40 passed / 8.44초**. 합성·mock 테스트이며 실제 모델 호출이 아니다.
- 오프라인 계약 평가: **3/3 기대 결과 일치**. 잘못된 JSON 1건 거절, 규칙 불일치 1건 탐지. 모델 품질·지연·토큰 사용량·비용 추정은 미측정이다.
- Docker 텍스트 전용 이미지에서 위 테스트와 B runtime 합동 실행은 65 passed / 1 failed였다. 실패는 이미지에 `langchain_core`가 없어 요청 해석 mock 테스트를 import하지 못한 환경 문제였다. 해당 세 파일 전체를 의존성이 설치된 로컬 환경에서 다시 실행한 것이 위 40 passed 결과다. 이 실패를 제품 버그 수정이나 실제 AI 검증으로 해석하지 않는다.
- 실제 서비스 readiness는 `storage=postgres`, `ai_mode=rules-only`, `external_ai=disabled`다.

브라우저 timeout 20초·서버 요청 예산 15초·추천 admission 1개 및 기존 Ollama 병렬 1개 제한은 유지했다. 모델 성능에 근거한 조정은 없으며, 5단계에서 확인되는 DB 중심 흐름의 실제 지연은 별도 기록한다.

원격 main `eaea05e` 기준을 유지하며 이번 구현·문서 변경은 커밋·푸시하지 않았다. 다음은 5단계 핵심 흐름 통합 검증이다.
