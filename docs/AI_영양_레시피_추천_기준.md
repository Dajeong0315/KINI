# AI 영양 레시피 추천 기준

## 1. 목적과 원칙

- 냉장고 재고, 재료 신선도, 개인 식사 기록, 영양 목표, 생활습관 전략, 취향, 조리 조건을 함께 고려해 메뉴를 추천한다.
- 개인 건강·식이·식사 기록은 기본적으로 기기 내부에서 처리한다.
- 추천 순위는 고정된 규칙과 버전 관리되는 데이터에 따라 계산한다. 동일한 입력값·규칙 버전·DB 버전에서는 동일한 순위를 반환해야 한다.
- AI/Ollama는 계산 결과의 설명, 사용자 입력 해석, 조정안 표현을 담당한다. 영양 계산, 제한 조건 판정, 후보 순위 결정은 규칙 엔진이 담당한다.
- AI가 생성한 재료 변경안은 규칙 엔진의 재료·단위·알레르기·영양 검증을 통과한 경우에만 제공한다.

## 2. 온디바이스 우선 아키텍처

| 구성 | 처리 위치 | 내용 |
| --- | --- | --- |
| 개인 프로필 | 기기 내 암호화 저장소 | 건강 주의사항, 알레르기, 식이 제한, 목표, 선호, 평소 식사량 |
| 냉장고 재고 | 기기 내 암호화 저장소 | 식재료, 수량, 입고일, 개봉일, 보관 위치, 신선도 상태 |
| 식사·섭취 기록 | 기기 내 암호화 저장소 | 메뉴, 실제 섭취량, 시간대, 영양 누적량 |
| 추천 규칙 엔진 | 기기 | 제한 필터, 영양 계산, 소비 권장도, 후보 점수화, 정렬 |
| Ollama | 기기 우선 | 질의 해석, 추천 이유·조리 설명·대안 문구 생성 |
| 공용 DB | 서버 배포 후 기기 캐시 | 레시피, 식품영양성분, 표준 단위, 보관 기준, 규칙 버전 |
| 동기화·백업 | 사용자 선택 시 | 사용자 기기 암호화 키 기반 암호화 백업을 우선 검토 |

### 2.1 서버 역할

- 공용 레시피 DB, 식품영양성분 DB, 식재료 표준 단위 DB, 보관 기준 DB, 추천 규칙 배포
- 공용 데이터의 버전 관리 및 무결성 검증
- 사용자가 동의한 경우에만 암호화된 동기화·백업 지원
- 개인별 원본 건강정보, 식사 기록, 냉장고 재고를 기본 수집·분석하지 않음

### 2.2 데이터 보안 규칙

- 건강정보, 알레르기, 섭취 기록, 냉장고 재고는 기본적으로 기기 내 암호화 저장한다.
- 클라우드 AI를 사용해야 할 경우 이름, 계정 식별자, 건강 상태 원문, 전체 식사 이력, 가족 관계 정보를 전송하지 않는다.
- 클라우드 전송이 필요한 경우에도 기기에서 계산한 최소 비식별 요청만 전송한다.
- AI 요청·오류 로그에 개인 건강정보·식사 기록·재고 원문을 저장하지 않는다.
- 제품 개선용 데이터 수집은 기본 비활성화하고 별도 동의를 받는다.
- 가족 공유는 구성원별 열람·수정 권한과 동의를 분리한다.
- 사용자가 삭제를 요청하면 로컬 데이터, 동기화 데이터, 분석 데이터의 삭제 범위와 상태를 제공한다.
- 개인 데이터는 모델 학습에 기본 사용하지 않는다.

### 2.3 버전 관리

추천 결과에 다음 버전을 함께 저장한다.

```text
recommendation_rules_version
recipe_db_version
nutrition_db_version
unit_conversion_db_version
storage_guideline_db_version
model_prompt_version
```

## 3. 생활습관 개선 전략

사용자는 주요 전략 1개와 보조 전략 1개를 선택할 수 있다. 영양 균형과 안전 제한은 전략 선택과 무관하게 공통 적용한다.

| 전략 | 핵심 목표 | 주요 평가 지표 | 레시피 조정 방향 |
| --- | --- | --- | --- |
| 영양 균형 개선 | 영양 결손·편중 완화 | 주요 영양소 충족도, 식품군 다양성, 최근 식사 편중도 | 부족 식품군·영양소 보완 |
| 체중·열량 관리 | 개인 목표에 맞는 열량·포만감 관리 | 목표 열량 적합성, 열량 밀도, 단백질·채소 비율 | 분량, 밥·채소 비율, 기름·소스 조정 |
| 나트륨 섭취 관리 | 과도한 나트륨 완화 | 식사별·일일 나트륨 추정량, 조미료 사용량 | 저염 조리법, 소스 감량·대체 |
| 단백질 섭취 관리 | 적정 단백질 섭취 지원 | 목표 대비 부족량, 끼니별 분배, 공급원 다양성 | 단백질 식재료 추가·대체·분량 조정 |
| 채소 섭취 개선 | 채소 섭취량·다양성 확대 | 채소 중량, 채소 종류 수, 최근 채소 편중도 | 채소 추가·대체·비율 확대 |

### 3.1 혈당 관리

- 초기 버전에서는 의료·건강상 주의사항 프로필로 처리한다.
- 별도 전략으로 분리하려면 탄수화물량·정제 탄수화물 비중·식이섬유·단백질 조합·개인 의료 정보의 검증 기준을 마련한 후 적용한다.
- 의료진 권고 또는 사용자가 직접 설정한 제한은 모든 전략보다 우선한다.

## 4. 입력 데이터 모델

### 4.1 사용자 프로필

| 구분 | 데이터 | 활용 |
| --- | --- | --- |
| 기본 정보 | 연령대, 성별, 키, 체중 | 기본 목표 산정 참고 |
| 활동 정보 | 활동량, 운동 빈도·시간 | 열량·단백질 목표 보정 |
| 식사 패턴 | 하루 식사 횟수, 주 식사 시간대 | 끼니별 목표 배분 |
| 평소 식사량 | 밥·면·빵·반찬·간식 평균 섭취량 | 1인분·끼니별 섭취량 모델 |
| 목표 | 주요·보조 전략, 직접 설정 목표 | 점수 가중치·영양 목표 |
| 건강 주의사항 | 알레르기, 식이 제한, 의료진 권고 | 후보 제외·경고 |

| 가족 정보 | 구성원, 공동 식사 빈도, 권한 | 공통 메뉴·개인별 조정 |

### 4.2 평소 식사량 입력 규칙

- 선택형 입력을 우선 사용한다. 예: `밥 2/3공기`, `달걀 1개`, `반찬 3종`, `야식 주 2회`.
- 선택형 값은 표준 중량으로 변환해 개인별 기본 식사량 모델을 생성한다.
- 실제 식사 기록이 충분히 쌓이면 최근 `N일`의 실제 평균 섭취량을 초기 프로필 값보다 우선한다.

```text
개인별 기준 식사량 =
초기 프로필 기반 표준 식사량
→ 최근 N일 실제 평균 식사량으로 점진 대체
```

## 5. 수량 표준화 및 불확실성 처리

### 5.1 단위 변환

내부 영양 계산 단위는 `g`, `ml`, `개`로 표준화한다.

| 입력 표현 | 식재료 | 표준 매핑 예시 |
| --- | --- | ---: |
| 한 줌 | 시금치 | 50g |
| 한 줌 | 견과류 | 25g |
| 한 컵 | 우유 | 200ml |
| 1큰술 | 간장 | 15ml |
| 1작은술 | 소금 | 5g |
| 적당량 | 식용유 | 기본 5ml |
| 1봉 | 두부 | 상품 라벨 중량 우선 |

### 5.2 변환 적용 규칙

```text
1. 상품 라벨 또는 사용자가 입력한 실제 중량이 있으면 실제값 사용
2. 식재료·상태·표현이 일치하는 표준 단위값이 있으면 표준값 사용
3. 표준값이 없으면 분류 기반 기본값을 사용하고 불확실성으로 표시
4. 영양 영향이 큰 재료의 수량이 불확실하면 사용자 확인 요청
5. 불확실한 재료를 영양 계산에서 제외하지 않음
```

### 5.3 사용자 확인 규칙

| 조건 | 처리 |
| --- | --- |
| 소량 재료이고 신뢰도 높은 표준값 존재 | 자동 적용 |
| 기름, 설탕, 소스, 고기 등 열량·나트륨·단백질 영향이 큰 재료 | 표준값으로 임시 계산 후 확인 요청 |
| 식재료 크기 차이가 큰 경우 | 표준값 범위와 함께 확인 요청 |
| 입력값이 표준 범위를 크게 벗어나는 경우 | 확인 요청 |

```text
영양 추정 정확도
- 높음: 주요 재료의 실제 중량 확정
- 보통: 소량 재료에만 표준 중량 적용
- 낮음: 열량·나트륨·단백질 영향이 큰 재료의 중량 미확정
```

## 6. 영양 계산 규칙

### 6.1 레시피 영양성분

```text
메뉴 영양소 총량 =
Σ(재료 사용량 g 또는 ml ÷ 영양 DB 기준량 × 재료별 영양성분)

1인분 영양소 = 메뉴 영양소 총량 ÷ 실제 제공 인분 수
```

- 원본 레시피 영양값은 참고값으로만 사용한다.
- 재료 추가·제거·대체·분량 변경 후에는 변경된 재료 목록으로 반드시 재계산한다.
- 영양 정보가 없는 재료 비율이 설정 임계값을 초과하면 자동 추천 후보에서 제외한다.

### 6.2 개인별 목표 우선순위

```text
의료진 권고 또는 사용자가 직접 설정한 목표
→ 사용자 프로필 기반 목표
→ 일반 기본값
```

### 6.3 일일 남은 목표량

```text
일일 남은 목표량 = max(0, 일일 목표량 - 오늘 누적 섭취량)

목표 대비 부족률 = 일일 남은 목표량 ÷ 일일 목표량
```

### 6.4 끼니별 목표 배분

```text
끼니별 기본 목표량 = 일일 목표량 × 해당 끼니의 개인별 평균 섭취 비중

해당 끼니 권장 보완량 =
min(일일 남은 목표량, 끼니별 기본 목표량 + 보정 허용량)
```

- 개인별 평균 섭취 비중은 프로필과 최근 실제 식사 기록에서 산출한다.
- 한 끼에 영양소를 과도하게 몰아주지 않도록 영양소별 끼니 상한을 적용한다.
- 최근 식사 기록이 부족하면 프로필 기반 식사 횟수와 기본 비율을 사용한다.

## 7. 식재료 보관 기준 및 소비 권장도

### 7.1 원칙

- 표준 보관 기간은 추천 우선순위를 위한 소비 권장 기준이며 식품 안전을 보장하는 절대 기준이 아니다.
- 곰팡이, 점액, 비정상 냄새, 심한 변색, 사용자 입력 `unsafe` 상태가 있으면 기간 계산과 무관하게 추천에서 제외한다.
- 실제 제품의 소비기한·보관 지시가 표준 기준보다 우선한다.

### 7.2 최종 소비 권장일

```text
기본 소비 권장일 = 입고일 + 식재료별 표준 보관 기간

최종 소비 권장일 = min(
  기본 소비 권장일,
  실제 제품 소비기한(입력된 경우),
  개봉 후 소비 권장일(해당하는 경우)
)
```

- 개봉 후 보관 기준이 더 엄격한 식재료는 `개봉일`을 기준으로 계산한다.
- 보관 위치가 권장 보관 방식과 다르면 보관 기간을 단축한다.
- 냉동 보관 시 해당 식재료의 냉동 보관 기준으로 다시 계산한다.
- `use_soon` 상태는 소비 권장도를 상향한다.

### 7.3 소비 권장도

```text
기준 시작일 = 개봉 후 기준이 적용되면 opened_at, 아니면 received_at

경과 비율 =
(현재 시각 - 기준 시작일)
÷
(최종 소비 권장일 - 기준 시작일)
```

| 경과 비율 | 상태 | 소비 우선도 |
| ---: | --- | ---: |
| 0~50% | 여유 있음 | 0.20 |
| 50~75% | 계획 소비 권장 | 0.50 |
| 75~90% | 빠른 소비 권장 | 0.80 |
| 90~100% | 오늘 우선 소비 권장 | 1.00 |
| 100% 초과 | 상태 확인 필요 | 자동 추천 보류 |

## 8. 추천 절차

```text
1. 식사 참여자, 시간대, 조리 시간, 도구, 추가 구매 가능 여부 확인
2. 개인·가족 프로필 및 냉장고 재고 로드
3. 재고별 소비 권장도 계산
4. 해당 끼니의 영양 목표·남은 목표량 계산
5. 레시피 후보 검색
6. 하드 제약 필터 적용
7. 후보별 영양·재고·전략·선호·실행 가능성 점수 계산
8. 맞춤 재료·분량 조정안 생성
9. 조정안에 대해 제한 조건·영양정보 재검증
10. 동점 규칙에 따라 정렬
11. 상위 추천, 조정 내용, 계산 근거, 대안 제공
```

## 9. 하드 제약 필터

다음 조건 중 하나라도 참이면 후보에서 제외한다.

```text
- 알레르기 유발 재료 포함
- 식이 제한 위반
- 사용자 건강상 제한 또는 의료진 권고 위반
- 변질·섭취 부적합 재료 포함
- 조리 시간·도구 조건 불충족
- 필수 재료 부족 및 허용 가능한 대체재 없음
- 공동 식사 참여자 중 한 명이라도 공통 메뉴를 섭취할 수 없음
- 영양 정보 누락 비율이 설정 임계값 초과
```

나트륨 등 목표를 초과한 메뉴는 사용자 설정에 따라 `제외` 또는 `경고 후보`로 분류한다. 알레르기·안전·의료상 제한은 항상 제외한다.

## 10. 후보 점수 계산

모든 항목 점수는 `0~100`으로 정규화한다.

### 10.1 재고 소진 점수

```text
재료별 소진 기여도 = min(레시피 사용량 ÷ 현재 재고량, 1.0)

재료별 재고 기여 점수 =
소비 우선도 × 소진 기여도 × 재료 중요도

레시피 재고 소진 점수 = Σ(재료별 재고 기여 점수)를 0~100으로 정규화
```

### 10.2 단백질 보완 점수

```text
단백질 보완 비율 =
min(메뉴 1인분 단백질 ÷ 해당 끼니 권장 단백질 보완량, 1.0)

단백질 보완 점수 = 단백질 보완 비율 × 100

단백질 초과 패널티 =
max(0, 메뉴 단백질 - 끼니별 단백질 상한)
÷ 끼니별 단백질 상한 × 패널티 계수
```

### 10.3 나트륨 적합 점수

```text
나트륨 비율 = 메뉴 1인분 나트륨 ÷ 남은 나트륨 예산
```

| 나트륨 비율 | 점수 |
| ---: | ---: |
| 0~0.5 | 100 |
| 0.5 초과~0.8 | 80 |
| 0.8 초과~1.0 | 50 |
| 1.0 초과 | 제외 또는 경고 후보 |

### 10.4 채소 점수

```text
채소 사용량 점수 = min(채소 g ÷ 끼니별 채소 목표 g, 1.0) × 70
채소 다양성 점수 = min(채소 종류 수 ÷ 3, 1.0) × 30
채소 점수 = 채소 사용량 점수 + 채소 다양성 점수
```

### 10.5 기타 점수

| 점수 | 기준 |
| --- | --- |
| 열량 적합 점수 | 해당 끼니 열량 목표 범위와의 거리 |
| 영양 균형 점수 | 주요 영양소·식품군 결손 보완, 과잉 방지 |
| 선호 점수 | 선호 재료·맛·조리법 반영, 비선호 재료 회피 |
| 실행 가능성 점수 | 조리 시간, 도구, 난이도, 추가 구매, 비용 |
| 다양성 점수 | 최근 메뉴의 주재료·조리법·맛 중복 회피 |

### 10.6 최종 점수

```text
최종 점수 =
(재고 소진 점수 × 재고 가중치)
+ (공통 영양 균형 점수 × 공통 가중치)
+ (주요 전략 점수 × 주요 전략 가중치)
+ (보조 전략 점수 × 보조 전략 가중치)
+ (선호 점수 × 선호 가중치)
+ (실행 가능성 점수 × 실행 가중치)
+ (다양성 점수 × 다양성 가중치)
- 초과·반복·추가 구매 패널티
```

| 항목 | 평상시 | 임박 재료 존재 시 |
| --- | ---: | ---: |
| 재고 소진 | 15% | 30% |
| 공통 영양 균형 | 15% | 15% |
| 주요 전략 | 30% | 25% |
| 보조 전략 | 15% | 10% |
| 선호 | 10% | 8% |
| 실행 가능성 | 10% | 7% |
| 다양성 | 5% | 5% |

가중치는 규칙 버전으로 관리하며 AI/Ollama가 임의로 변경하지 않는다.

## 11. 충돌 해결 규칙

| 충돌 | 처리 우선순위 |
| --- | --- |
| 식품 안전 vs 모든 조건 | 식품 안전 우선, 재료·후보 제외 |
| 알레르기·의료 제한 vs 모든 조건 | 알레르기·의료 제한 우선, 후보 제외 |
| 임박 재료 vs 일반 영양 부족 | 두 조건을 동시에 충족하는 메뉴 우선 탐색 |
| 주요 전략 vs 보조 전략 | 주요 전략 점수 우선 |
| 체중 관리 vs 단백질 관리 | 열량 목표 안에서 단백질 밀도 높은 메뉴 우선 |
| 나트륨 관리 vs 취향 | 저염 조정안 우선, 불가하면 대안 제시 |
| 가족 전략 충돌 | 공통 기본 메뉴 + 개인별 분량·소스·토핑·반찬 조정 |
| 완전 충족 메뉴 없음 | 상위 대안 2~3개와 충족·미충족 조건 표시 |

## 12. 동점 및 불확실성 처리

동점은 다음 순서로 정렬한다.

```text
1. 최종 점수 높은 순
2. 필수 임박 재료 사용량 많은 순
3. 주요 전략 점수 높은 순
4. 추가 구매 비용 낮은 순
5. 조리 시간 짧은 순
6. recipe_id 오름차순
```

```text
영양·재료 데이터 미확정 처리
- 주요 재료 영양정보 미매칭 비율이 임계값 초과: 자동 추천 제외
- 일부 정보 미확정: 영양 추정 정확도 표시
- 수량 불명확: 표준 분량으로 임시 계산 후 확인 요청
- AI/Ollama는 누락된 영양정보를 임의 생성하지 않음
```

## 13. 가족 공동 식사 규칙

- 모든 참여자의 알레르기·의료 제한을 공통 하드 제약으로 적용한다.
- 공통 기본 메뉴를 먼저 선정하고, 개인별 분량·소스·토핑·반찬을 조정한다.
- 공통 메뉴로 해결할 수 없는 제한이 있으면 개인별 대안을 제공한다.
- 구성원별 영양 계산과 목표 달성률은 분리해 계산한다.

## 14. Ollama 입력·출력 규칙

### 14.1 Ollama에 제공 가능한 입력

```json
{
  "recommended_recipes": [],
  "validated_adjustments": [],
  "recommendation_reasons": [],
  "nutrition_summary": {},
  "uncertainty_flags": [],
  "response_style": "concise_ko"
}
```

- 입력값은 규칙 엔진이 검증한 메뉴·재료·영양 수치·추천 사유만 사용한다.
- 건강 상태 원문, 전체 식사 이력, 계정 식별자, 가족 관계 원문은 제공하지 않는다.

### 14.2 Ollama 출력 제한

- 검증된 후보 외의 메뉴를 확정 추천으로 제시하지 않는다.
- 검증되지 않은 재료 대체·영양 수치·의학적 효능을 단정하지 않는다.
- 조정안을 새로 제안하는 경우 `검증 필요` 상태로 규칙 엔진에 반환한다.
- 최종 사용자 문구에는 추천 이유, 재료 조정, 예상 영양정보, 불확실성, 대안을 포함한다.

## 15. 사용자 표시 항목

```text
- 추천 메뉴명 및 조리 시간
- 사용 예정인 임박 재료와 사용량
- 주요 전략·보조 전략 충족 근거
- 조정 전후 재료와 분량
- 1인분 기준 예상 영양성분
- 영양 추정 정확도와 확인 필요 항목
- 충족하지 못한 조건 또는 경고
- 대안 메뉴 2~3개
```
