## 연결·보호 조건

- 원래 패치는 현재 Windows checkout에서 일반 check 실패, `--ignore-space-change` check 성공이었다.
  무조건 meal_feedback를 readiness에 요구하므로 그대로 운영 활성화하지 않았다.
- d3ec292 기준의 새 패치로 갱신하고 분리된 임시 복사본에서 check/apply 및 결과 일치를 확인했다.
  현재 로컬 실행기에는 해당 연결을 반영했다. 패치를 다시 적용하는 용도가 아니라 적용 이력/검토 자료다.
- `KINI_B_MEAL_FEEDBACK_ENABLED=0`이 기본. 이때 피드백 GET/PUT 404이며 기존 readiness에 테이블 요구가 없다.
- 1일 때만 Blueprint·GET/PUT allowlist를 활성화한다. 기존 인증·가구 권한·bounded process·15초 budget을 유지한다.
- 활성화된 readiness는 테이블 컬럼과 PostgreSQL SELECT/INSERT/UPDATE 권한을 각각 확인한다.
  테이블 누락 시 503이며 요청 시 자동 DDL/seed/가짜 저장을 하지 않는다.
- 선택지 파일은 `/etc/kini-b/meal-feedback-options.v1.json`, 환경 변수는
  `KINI_MEAL_FEEDBACK_OPTIONS_FILE`. installer와 서버 설정에 연결한다.
  mock_/test_ 접두사는 파일 loader가 거절한다. 미설정 submitted 503도 유지한다.
- 운영 schema·제한 앱 역할이 준비되지 않아 cloud 기능 flag는 0을 유지한다.
  승인 선택지나 개인화 가중치 때문에 비활성화한 것이 아니다.
