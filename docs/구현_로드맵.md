# KINI 구현 로드맵

초기 점검: 로컬 음성 API와 별도의 SQLite 가족 추천 데모, 개인화 기록이 있었다. 데모 영양값과 프로필은 실제 안전·의료 판단에 적합하지 않다. 기존 재고 JSON과 SQLite는 별도다. 초기에는 조리 변경 후 영양 재계산이 없었고, 인증 및 저장 암호화도 없었다.

진행 상태: Phase 1~6은 안전한 데모 범위에서 부분 구현했다. 조리 세션의 정량 재료 변경은 영양을 재계산한다. 실제 식품 데이터·보관 지침, 단위 변환 데이터, 알레르기 별칭·교차 접촉, 개별 분량 최적화, 실제 기기·모델 평가, 30개 자연어 질문 평가셋, 인증·암호화 및 삭제·복구는 아직 필요하다. 재현 지문은 전체 DB 버전이나 재현 가능한 완전 스냅샷을 대체하지 않는다.

## 데이터 import 운영 전 필수 TODO

공식 식품·영양·알레르겐 데이터를 실제 API 또는 파일에서 가져와 `published` release로 반영하기 **전** 아래 기능을 구현하고 검증한다. 현재 fixture 기반 import 데모와 휴대폰 UX 검증에는 적용하지 않는다.

- 전체 페이지 수집: 원천 API의 페이지네이션을 끝까지 수집하고, 페이지 수·수집 건수·누락 여부를 기록한다.
- raw artifact 보관: release별 원본 응답을 Git 제외 경로 또는 승인된 별도 저장소에 보관하고 checksum·보관 참조를 남긴다.
- 대량 import resume: 중단된 import를 같은 release에서 안전하게 재개하며, 이미 검증된 페이지를 중복 적재하지 않는다.
- 운영 dry-run: 소규모 및 전체 데이터셋 dry-run, quarantine 리포트, publish 전 승인 절차를 마련한다.

완료 조건: 네트워크 실패·프로세스 중단·형식 오류가 있어도 현재 published release는 변하지 않고, 원천 release를 재현·검토·rollback할 수 있다.

## Phase 1 — 데이터와 식품 상태
- 목표/가치: 기존 DB를 보존하면서 기한과 상태를 명시해 불확실한 재고를 구분한다.
- 파일/데이터/API: recommendation_repository, 신규 freshness 서비스, recommendation_engine 및 테스트. 기존 inventory_items에 선택적 날짜·위치 필드를 마이그레이션한다.
- 안전: 소비 권장도는 안전 보증이 아니며 unsafe와 기한 경과는 제외한다. 정보가 없으면 추정하지 않고 알린다.
- 검증/완료: 기존 DB 마이그레이션, 기한·상태·정보 누락 테스트 및 전체 pytest 통과.

## Phase 2 — 추천과 영양
- 목표/가치: 재현 가능한 버전·근거와 참여자별 목표를 제공한다.
- 파일/데이터/API: recommendation_engine, repository, models, 테스트; 결과에 데이터 상태 지문과 끼니 목표를 추가한다.
- 안전: 하드 필터 우선, 누락 영양은 보수적으로 제외, 식품 안전을 단정하지 않는다.
- 검증/완료: 가족 조합, 누락 영양, 고정 상태에서 순위, 스냅샷 테스트와 전체 pytest 통과.

## Phase 3 — 조리 세션과 섭취
- 목표/가치: 선택 메뉴의 변경 재료·양을 검증하고 영양을 재계산해 확인 후 식사 기록을 만든다.
- 파일/데이터/API: cooking 서비스, repository·models·API, 조리 세션·재료 스냅샷 테이블; 세션 생성·조회·변경·질문·완료 API.
- 안전: 참여자 제한·알레르기·영양정보·수량을 다시 검증하고 불명확한 양은 확인 요청한다. LLM 초안은 확정하지 않는다.
- 검증/완료: 버섯 제외, 스팸 반 통 확인 요청, 짠 국물 안내, 재계산·기록·실패 원자성 테스트 및 전체 pytest.

## Phase 4 — RAG와 모델 경계
- 목표/가치: 출처가 표시된 일반 조리 안내와 안전한 오프라인 fallback을 제공한다.
- 파일/데이터/API: recommendation_rag, recommendation_llm, prompts, cooking 서비스; 문서 버전과 검색 결과 출처를 제공한다.
- 안전: 개인 데이터를 RAG에 넣지 않고 검색은 추천 필터·순위에 사용하지 않는다. 외부 검색은 구현하지 않고 제한 설정만 둔다.
- 검증/완료: 검색 실패, Ollama 실패, 결과 출처 및 순위 독립성 테스트와 전체 pytest.

## Phase 5 — 평가와 사용 경로
- 목표/가치: 안전·결정성 회귀를 반복 측정하고 API를 실제 시나리오로 사용할 수 있다.
- 파일/데이터/API: 평가셋·benchmark 스크립트·README 및 필요한 API 데모; 개인정보가 없는 구조화 조건을 사용한다.
- 안전: 평가 로그는 원문 건강 정보와 비밀키를 기록하지 않는다.
- 검증/완료: 30개 이상 시나리오, 시간 측정 및 기존 음성 테스트를 포함한 전체 pytest.

## Phase 6 — 보안 경계와 외부 준비
- 목표/가치: 개인정보 분류와 삭제·백업 인터페이스, 미구현 사항을 명확히 한다.
- 파일/데이터/API: 보안 서비스·문서·설정; 실제 삭제나 내보내기는 인증·권한 정책 없이는 실행하지 않는다.
- 안전: 원문·키를 로그에 저장하지 않고 외부 전송은 기본 비활성화한다. 인증·가족 권한·암호화·동기화는 정책과 기반 시설 필요.
- 검증/완료: 외부 설정 없이 안전한 거부·fallback과 테스트, 실제 사용자 데이터 전 필수 보안 작업을 문서화한다.
