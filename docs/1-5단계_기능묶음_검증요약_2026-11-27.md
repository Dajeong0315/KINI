# KINI 1~5단계 첫 기능 묶음

최종 확인일: 2026-11-27 KST. 사용자 요청에 따라 구현 브랜치에 커밋·푸시할 범위의 요약이다.

- 원격 main `eaea05e`를 기준으로 기존 B 서버 코드를 재사용·통합했다. 원본 폴더의 다른 미커밋 변경과 SQLite를 보존했다.
- 서버는 제한된 앱 역할·TLS 검증으로 Supabase PostgreSQL `kini_private`에 연결한다. 001~009 migration과 public SELECT 계약을 검증했다. 공개 카탈로그를 복제하거나 수정하지 않고 승인된 release·명시적 재료 매핑으로 영양을 읽는다.
- 재고 정규화 인증, 식사 이력·상세·개인 영양 리포트, 재로그인·만료·가구 전환·조회 실패·저장 응답 유실을 연결했다.
- 입고마다 새 재고 묶음을 생성한다. A 확정에서만 재고를 차감하며 같은 이벤트 재전송은 1회 반영한다. B 완료는 개인 섭취량과 영양 스냅샷을 저장한다.
- 사용자 휴대폰 전체 흐름 확인과 서버 DB 대조까지 통과했다. 시연 계정의 식사 기록 3건은 에이전트 시험 2건과 사용자 시험 1건이며 중복 저장이 아니다.
- 보조 검사·OpenAI 설명은 사용자 결정으로 비활성, 호출 0회·USD 0이다. 기본 로컬 모델은 `qwen2.5:3b-instruct-q4_K_M`이다. 실제 AI 품질·성능 완료로 표시하지 않는다.
- 기존 B의 식후 피드백 모듈과 시험은 통합에 포함되지만 실행 flag는 0이다. 6~8단계 완료·추가 기능 활성화는 이번 범위가 아니다.

## 검증과 한계

별도 PostgreSQL의 조리·동시성·이력·리포트 149개 통과 후, 조리 변경 최적화에 대해 새 DB에서 관련 63개를 재검증했다(부분집합이므로 합산하지 않음). 화면 14개, API 클라이언트 12개, 로컬 모델 설정 13개가 통과했다. 실제 배포 HTTPS의 PC Chrome 재로그인·상세·리포트 시험도 통과했다. 실제 휴대폰 전체 흐름은 사용자 보고로 확인했으며 기종·브라우저 버전·휴대폰 지연은 미확인이다.

정상 조리 변경은 15초 timeout에서 8.937초로 개선됐다. B 저장 14.966초를 근거로 서버 요청 예산을 18초로 조정했고 브라우저 20초와 추천 admission 1개는 유지했다. 단일 정상 측정이며 동시 부하·백분위 지연 보장이 아니다. 영양은 원재료 기준 추정치다.

## 배포 추적
