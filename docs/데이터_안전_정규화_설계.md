# 데이터 안전과 정규화 설계

현재 식재료·영양·목표는 기능 검증용 임의 데모이며 실제 식품 데이터나 알레르기 안전성의 근거가 아니다. 출처 등급은 `demo`(예시), `user_entered`(사용자 입력), `official_imported`(공식 원본을 추적 가능한 형태로 수입), `verified_product`(특정 제품 라벨 확인), `unknown`(미상)이다. 등급은 안전 보증이 아니며 원본·버전·검증 시각과 별도로 관리한다.

재료명은 정확한 정규명과 명시 별칭만 매칭한다. 수량이나 조사는 제한적으로 제거하고, 브랜드·가공·복합식품은 일반 재료로 추정하지 않는다. 제품 라벨이 필요한 재료와 불명확한 이름은 확인을 요청한다. 알레르겐 태그는 명시 충돌을 제외하기 위한 정보이며 태그 부재가 안전하다는 뜻이 아니다. 교차접촉은 자동 판정하지 않으며 제품 라벨과 사용자 확인이 필요하다.

질량 단위는 SI 배율만 자동 변환한다. 부피는 부피로만 변환하고, 중량 환산·개·컵·스푼·반 통·봉지는 특정 재료 또는 제품에 신뢰 가능한 환산 근거가 없으면 확인 요청한다. 영양값·기준 중량·재료 양이 없거나 유효하지 않으면 해당 후보를 제외한다. 불확실한 복합재료 및 라벨 미확인 제품은 알레르기 참여자 후보에서 제외하며, 건강 제한의 판정에 필요한 영양값이 없으면 점수 감점 대신 제외한다. 결과가 없으면 no_safe_recommendation을 반환한다.

데모에서 가능한 것은 명시된 예시 데이터에 한정된 규칙 흐름과 불확실성 표시다. 실제 영양·알레르기·식품 안전의 확정 판단이나 의료 진단은 불가능하다. RAG는 일반 조리·보관 문서용이며 판단·영양·순위를 바꾸지 않고 개인정보와 대화 원문을 보내지 않는다. Tavily는 호출하지 않는다.

향후 식품안전나라·식약처 등 공식 import는 원본 식별자·발행일·버전·라이선스·기준량·단위·상태·알레르겐 범위 및 검증 기록을 보존하는 staging과 검토 후 반영 절차가 필요하다. 공식 일반 식품과 특정 브랜드 라벨을 혼동하지 않으며 갱신·철회와 별칭 충돌도 처리해야 한다.

이번 단계는 하위 호환 SQLite 확장, 보수적 정규화·변환, 알레르겐 태그·라벨 검증, 품질 결과와 재고 입력 API 및 회귀 평가다. 실제 공식 DB 수집·연결, 포괄적 알레르겐 온톨로지·교차접촉 판정, 제품 라벨의 진위 검증, 의료 규칙 검증, 인증·암호화와 데이터 삭제·복구는 다음 단계다.
