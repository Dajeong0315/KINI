이전에는 C가 호출할 로그인 HTTP 경로가 없어, 토큰 없는 B 완료가 `401`을 반환했다. 이제 로그인 응답에서 받은 같은 토큰으로 A 재고 조회·출고 확인과 B 조리 완료를 호출할 수 있다. 요청의 가구 ID는 선택값으로만 사용하고 서버가 활성 계정·비밀번호·가구 소속·현재 역할을 확인한다. A가 이미 확정한 출고 ID를 B에 연결하면 B는 조리·섭취만 기록한다.

B 조리 서비스·차감 로직과 C 화면 코드는 이번에 수정하지 않았다. 회원가입·외부 로그인·전체 API 인증 개편도 포함하지 않는다.

## 최종 HTTP 계약

`POST /api/auth/login`

```json
{"login_name":"synthetic-owner","password":"<입력 비밀번호>","household_id":1}
```

성공은 `200`, 응답 필드는 `access_token`, `token_type: "Bearer"`, `expires_in: 3600`, `expires_at`(UTC Unix epoch 초), `household_id`, `role`이다. 비밀번호·토큰 원문은 로그나 이 문서에 기록하지 않는다.

- 형식 오류: `400`.
- 없는 계정·틀린 비밀번호·비활성 계정·미소속 가구: 공통 `401`과 `로그인 정보를 확인해 주세요.`.
- 이후 A 재고·B 완료에는 `Authorization: Bearer <access_token>` 사용.
- 토큰 누락 `401`, 세션·가구 권한 불일치 `403`, 타 가구 이벤트 확인 `404`.
- 출고 확인 부족·재사용: B 완료 `409`와 `inventory_confirmation_required`.

완전한 JSON 예시와 호출 순서는 [A 로컬 로그인 API](A_로컬_로그인_API.md), B 응답은 [C 연동 문서](C_API_연동_핸드오프.md)를 따른다.
