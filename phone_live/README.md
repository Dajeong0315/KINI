# KINI 통합 기본값

현재 main에서 별도 공개 Supabase 개수 재고 쓰기는 기본 비활성입니다. `phone_live`는 실제 comparer와 전·후 사진·결과 파일을 재사용하는 촬영 도구입니다. KINI g 재고는 저장된 `fridge_vision/captures/<capture_id>/result.json`을 루트 `scripts/vision_kini_bridge.py`로 후보 접수한 뒤 KINI 앱에서 실제 재료·g·lot을 확인해야 바뀝니다. 이 화면의 ‘DB에 반영’을 KINI 재고 확정 버튼으로 사용하지 마세요.

아래 구형 개수 재고 동기화 설명은 전용 DB에서 `VISION_ALLOW_LEGACY_SUPABASE_WRITE=1`을 명시한 경우에만 해당합니다. KINI API URL과 동시에 활성화되지 않습니다. 설치·촬영 방법은 재사용하되 기본 KINI 연결은 7단계 구현검증 문서를 따릅니다.


# 핸드폰 카메라 실시간 식재료 인식 (phone_live)

핸드폰 카메라 영상을 PC 로 보내 **`fridge_vision` 과 똑같은 인식 방식**(원본 YOLOE-v8m + CLIP 재확인 + 포장 식품 OCR, Unknown 처리)으로 실시간 인식하고,
**핸드폰 화면과 PC 화면 둘 다**에 물체 상자와 이름을 띄웁니다. 핸드폰의 전면·후면 카메라를 전환할 수 있습니다.

```text
핸드폰 브라우저 (/camera)                       PC (server.py)                          PC 브라우저 (/viewer)
  카메라 영상 ── JPEG 10장/초 (WebSocket) ──▶  모든 장을 그대로 ──────────────────────▶  핸드폰 화면
  상자·이름 ◀───────── 인식 결과 ────────────  쉬고 있으면 그 장으로 인식(빠른 설정) ───▶  상자·이름
  일시정지 → [🔍 식재료 파악하기] ── 1280폭 사진 (HTTPS POST /api/analyze) ──▶ 정밀 설정으로 다시 인식 ──▶ 결과 사진·상자
```

- **실시간 화면(빠른 설정)**: 한 장 약 0.55초 → **초당 약 1.8회** 갱신. 포장 이름(OCR)은 새로 읽지 않고, 최근 '식재료 파악하기'에서 읽은 같은 자리·같은 생김새의 포장 이름만 다시 씁니다 (그 전에는 '포장 식품(이름 모름)').
- **식재료 파악하기(정밀 설정)**: 일시정지한 화면을 더 큰 사진(1280 폭)으로 보내, 저장된 결과를 쓰지 않고 모든 후보 상자를 CLIP 으로 확인하고 모든 포장을 OCR 합니다. 한 장 약 9~15초 (사진 전체를 한 번 OCR).
- 화면은 끊기지 않고, 상자는 가장 최근 결과로 그려집니다. 핸드폰에는 앱 설치가 필요 없습니다 (Chrome·Safari 브라우저만).

---

## 1. 준비 (처음 한 번)

1. `fridge_vision` 폴더가 **같은 상위 폴더**에 있어야 합니다 (모델·설정을 그대로 불러옴).
   ```text
   Downloads/fridge_vision/
     fridge_vision/   ← 인식 코드·모델 (먼저 한 번 실행해서 모델을 받아 두세요)
     phone_live/      ← 이 폴더
   ```
2. 패키지 설치
   ```bash
   pip install -r requirements.txt
   ```
3. **PC 와 핸드폰을 같은 와이파이**에 연결합니다.

---

## 2. 실행

```bash
python server.py
```
또는 `run.bat` 더블클릭. 터미널에 접속 주소가 나옵니다.

```text
 핸드폰 (같은 와이파이)에서 열기:
   https://192.168.10.7:8443/camera
 PC 화면:  https://localhost:8443/viewer
```

1. **PC** 브라우저에서 `https://localhost:8443/viewer` 를 엽니다. 오른쪽에 **QR 코드**가 나옵니다.
2. **핸드폰** 카메라로 QR 코드를 찍거나 `https://<PC IP>:8443/camera` 를 직접 입력합니다.
3. 처음 접속하면 **"연결이 비공개로 설정되어 있지 않습니다 / 안전하지 않음"** 경고가 나옵니다.
   이 PC 가 직접 만든 시험용 인증서라서 그렇습니다. **[고급] → [계속 / 이 웹사이트 방문]** 을 누릅니다.
   (PC 브라우저에서도 같은 경고가 한 번 나옵니다.)
4. 핸드폰에서 **[카메라 켜기]** → 카메라 권한 **허용**.
5. Windows 방화벽 창이 뜨면 **개인 네트워크 허용**을 누릅니다. 핸드폰이 접속하지 못하면 대부분 이 문제입니다.

### 핸드폰 화면 (`/camera`)

| 기능 | 설명 |
|---|---|
| 상자 + 이름 | 하늘: 포장 글씨로 읽은 이름, 초록: 생김새로 인식(신뢰도 75% 이상), 노랑: 사용자가 이름 붙인 품목, 빨강: Unknown(❓ 이름?) |
| **모르는 물체 안내** | Unknown 이 1개 이상이면 위쪽에 "❓ 모르는 물체 N개 — 빨간 상자를 눌러 이름을 알려 주세요". 상자를 누르면 이름 입력 (포장 글씨를 읽었으면 입력 칸에 미리 채워짐) |
| **⟲ 카메라 전환** | 후면 ↔ 전면. 전면은 거울 화면으로 보이고 상자도 맞춰서 뒤집힘 |
| 일시정지 | 화면 멈춤 + 전송 중지. **[🔍 식재료 파악하기]** 버튼이 나타남 |
| **🔍 식재료 파악하기** | 멈춘 화면을 정밀 설정으로 한 번 더 인식 → "식재료 파악 결과 · 5종 8개 · 1.8초" 와 목록, 상자. PC 화면에도 그 사진과 결과가 뜸. [다시 시작]을 누를 때까지 유지 |
| 신뢰도 슬라이더 | 이 점수보다 낮은 상자는 숨김 (기본 20% — Unknown(0.25 이상)이 숨지 않게) |
| **Unknown 상자 누르기** | 이름 입력 → PC 가 생김새를 기억해서 다음부터 그 이름으로 인식 (`fridge_vision/user_labels.json` 에 저장, fridge_vision 과 공유). 식재료 파악 결과 화면에서 이름을 붙이면 바로 다시 파악함 |
| 위쪽 표시 | PC 연결 상태, 인식 시간(ms), 초당 인식 횟수, 보고 있는 PC 화면 수 |

주소 옵션: `/camera?auto=1` (버튼 없이 바로 시작), `/camera?facing=user` (전면 카메라부터)

### 전/후 비교 → 재고 DB 반영 (`/compare`)

냉장고 문을 열기 **전**과 넣거나 꺼낸 **후**를 핸드폰으로 찍으면, 무엇이 들어오고 나갔는지 계산해 **Supabase 재고 DB 에 추가·삭제**합니다 (`fridge_vision` 의 `compare()` + `supabase_sync`, main.py 와 같은 규칙). 첫 화면의 **📷 전/후 비교** 또는 `https://<PC IP>:8443/compare`.

```text
┌──────────────────────┐
│ ① 전  [📸 전 촬영]   │  위 절반: 전 사진 (찍기 전에는 카메라 화면)
├──────────────────────┤
│ ② 후  [📸 후 촬영]   │  아래 절반: 후 사진 (찍을 때 전 사진이 흐리게 겹쳐 보여 같은 위치·각도를 맞추기 쉬움)
└──────────────────────┘
  [🔍 비교하기] → + 우유 1 (왼쪽 위 칸) / − 버터 1 … → [✅ DB 에 반영] [✖ 거절] [↺ 처음부터]
```

| 단계 | 동작 |
|---|---|
| 촬영 | ① 전 → ② 후. 각 칸의 [↺ 다시 찍기] 로 다시 찍음 (전을 다시 찍으면 후도 다시) |
| 비교하기 | 두 사진을 PC 로 보내 추가·제거 계산 (10~30초). 두 사진 위에 상자, 아래에 변경 목록·칸 위치 |
| 빨간 상자(Unknown) 누르기 | 이름 입력 → 기억하고(user_labels·갤러리) 같은 사진으로 다시 비교. **이름이 없는 물체는 DB 에 저장하지 않음** |
| ✅ DB 에 반영 | `capture` 1행 + `stock_event` 저장 → `confirm_stock_event()` 로 재고 반영. 결과 화면에 반영된 변경과 현재 DB 재고 |
| ✖ 거절 | 촬영 기록과 이벤트는 남기고 `reject_stock_event()` (재고 그대로) |

- 재고보다 많이 빼는 결과는 재고를 바꾸지 않고 "⚠️ 확인 필요" (이벤트는 대기 상태로 남음). 같은 결과를 두 번 반영해도 중복되지 않음.
- DB 에 연결할 수 없으면 `fridge_vision/state/db_outbox.jsonl` 에 쌓고 "DB 저장 대기 중 N건" 표시 → 다음 반영 때 다시 보냄.
- 위쪽 표시가 **재고 DB 연결**이 아니라 **DB 미설정**이면 `fridge_vision/.env` 의 `SUPABASE_URL`·`SUPABASE_SECRET_KEY` 를 확인 (비교는 됨).
- 사진은 PC 의 `fridge_vision/captures/phone-<시각>/before.jpg·after.jpg·result.json` 에 저장 (main.py 촬영과 같은 위치). DB 에는 사진 경로만 저장.
- 손에 든 핸드폰은 매번 다른 장면이라, 고정 카메라용 '위치·변화 기반 유지(트랙)'는 쓰지 않습니다. 등록한 용기를 다시 알아보는 갤러리는 그대로 씁니다.
- 전·후 사진의 위치가 크게 다르면 같은 물건이 '꺼냄 + 넣음'으로 잡힐 수 있습니다 → 겹쳐 보이는 전 사진에 맞춰 찍거나 핸드폰을 받쳐 두세요.

#### PC 에서 함께 보기 (`/compare-view`)
PC 브라우저에서 `https://localhost:8443/compare-view` (첫 화면의 **🖥 전/후 비교 보기**). `/viewer` 처럼 보기 전용이며 **PC 카메라는 쓰지 않습니다** (카메라 권한을 묻지 않음) — 오른쪽 QR 코드를 핸드폰으로 찍어 `/compare` 에 접속하면 핸드폰 카메라 화면이 PC 에 나옵니다.
- PC 에서 `/compare` 를 열면 카메라를 켜지 않고 자동으로 `/compare-view` 로 넘어갑니다 (핸드폰·태블릿은 촬영 화면. PC 에서 촬영 화면을 시험하려면 `/compare?phone=1`).
- PC 화면은 핸드폰이 연 화면을 따라갑니다: `/viewer` 를 켜 둔 채 핸드폰이 `/compare` 를 열면 PC 는 `/compare-view` 로, 핸드폰이 `/camera` 를 열면 다시 `/viewer` 로 자동 전환.
- 왼쪽 위·아래 절반: 핸드폰과 같은 ① 전 / ② 후 — 찍는 중인 칸은 핸드폰 화면이 실시간(초당 약 6장)으로, 후를 찍을 때는 전 사진이 흐리게 겹쳐 보임. 찍은 뒤에는 사진 + 인식 상자
- 오른쪽: 진행 단계, 비교 결과(+/− 목록·칸 위치·Unknown 안내), DB 반영 결과(반영·거절·확인 필요·대기 건수, 현재 DB 재고), 핸드폰 접속용 QR(`/compare`)
- 중간에 열어도 지금까지의 사진·결과가 바로 나옵니다. [화면 저장] 은 전·후 두 칸을 한 장의 PNG 로 저장
- 조작(촬영·비교·이름 입력·DB 반영)은 핸드폰에서만 합니다. 연결: 핸드폰 `/ws/compare?role=phone` → PC `/ws/compare?role=view`

### PC 화면 (`/viewer`)
- 핸드폰 화면(초당 약 10장) 위에 같은 상자·이름. 여러 PC·모니터에서 동시에 열 수 있습니다.
- 인식 시간, 초당 인식 횟수, 받은 화면 수, 인식된 물체 목록, 신뢰도 슬라이더
- [전체 화면], [화면 저장](PNG)
- 핸드폰 접속용 QR 코드와 주소

## 3. 핸드폰이 카메라를 못 열 때

핸드폰 브라우저는 **HTTPS 주소에서만** 카메라를 열어 줍니다. 그래서 서버가 PC 의 와이파이 IP 로 시험용 인증서(`certs/`)를 자동으로 만듭니다.

| 증상 | 해결 |
|---|---|
| 페이지가 안 열림 | 같은 와이파이인지, 방화벽에서 Python 을 허용했는지 확인. 주소는 `172.x` 말고 `192.168.x.x` 를 먼저 시도 |
| "카메라를 열 수 없습니다" | 주소가 `https://` 인지 확인. 브라우저 설정 → 사이트 설정 → 카메라 허용 |
| 인증서 경고에서 계속이 안 됨 (일부 iOS) | 경고 화면의 "세부사항 보기 → 이 웹 사이트 방문" |
| 와이파이가 다르거나 회사망이라 접속이 막힘 | **USB 방식(Android)**: USB 디버깅 켜고 `adb reverse tcp:8443 tcp:8443` → `python server.py --http` → 핸드폰에서 `http://localhost:8443/camera` (localhost 는 HTTPS 없이도 카메라 허용) |
| PC IP 가 바뀜 | 서버를 다시 켜면 인증서를 새 IP 로 자동으로 다시 만듦 |

## 4. 파일

| 파일 | 역할 |

| `static/compare.html` | 전/후 비교 화면 (위·아래 절반 촬영, 상자·변경 목록, Unknown 이름 입력, DB 반영·거절). 서버 API: `POST /api/compare`, `/api/compare/label`, `/api/compare/commit` |

## 5. 알려진 한계

- 인식 속도는 PC 에 달려 있습니다 (i7-9700 + 내장 그래픽 기준 실시간 한 장 약 0.55초, 식재료 파악하기 약 9~15초 (사진 전체 OCR 포함)). 핸드폰 영상은 실시간이지만 상자는 약 0.5~1초 늦게 따라옵니다. 실시간/정밀 설정은 `fridge_vision/config.py` 의 `DETECT_PROFILES`.
- 서버 시작에 약 25초 걸립니다 (YOLOE + CLIP + OCR 모델, 내장 그래픽용 CLIP 준비).
- 사용자 이름표의 "같은 자리" 기준(상자 위치)은 고정 카메라용입니다. 손에 든 핸드폰은 계속 움직이므로 생김새 유사도 0.95 이상일 때만 자동 적용되고, 다시 물어볼 수 있습니다.
- 영상·사진은 저장하지 않습니다. 단 Unknown 에 이름을 붙이면 그 물체의 생김새 특징값이 `fridge_vision/user_labels.json` 에 저장됩니다.
- 인증서는 시험용입니다. 공용 네트워크에서는 쓰지 마세요.
