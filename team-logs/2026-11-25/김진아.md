# 2026-11-25 | 김진아

## 오늘의 핵심

오늘은 서비스의 추진배경을 확정하고, 기존 식생활 관리 방식 및 삼성의 유사 서비스와 비교해 우리 서비스가 해결할 문제와 차별화 지점을 구체화했다. 저녁에는 DCX 분석 결과와 메인 타깃 내용을 최종 산출문서에 어떻게 반영할지 정리했다.

## 1. 추진배경은 ‘현재의 문제’를 중심으로 설명

- 추진배경에서는 서비스의 개선 기능을 먼저 강조하기보다, **건강한 식생활에 대한 관심이 실제 실천으로 이어지지 않는 이유**를 충분히 설명하기로 했다.
- 서비스의 해결 방향은 각 문제에 대한 짧은 시사점이나 추진배경의 마무리에서만 연결하고, 문제와 해결책이 한 표 안에서 뒤섞이지 않도록 한다.
- 전체 논리는 다음 순서로 구성한다.

  1. 건강한 식생활에 대한 관심은 높음
  2. 실제 영양 섭취와 식생활 실천 수준은 충분하지 않음
  3. 식사 준비·기록·판단·개인화 과정에서 지속적인 부담이 발생함
  4. 기존 앱 중심 관리만으로는 이 부담을 해결하기 어려움
  5. 실제 식사 행동이 발생하는 주방과 냉장고를 새로운 관리 접점으로 제안함

- 냉장고를 선택한 이유는 단순히 LG가 보유한 제품이기 때문이 아니라, **보유 재료 확인·메뉴 결정·조리·기록이 실제로 시작되는 공용 생활 접점**이기 때문이라고 설명한다.
- LG의 ThinQ, 식재료 인식, 레시피·주방가전 연동, 디스플레이·음성 기술은 개별 기능으로 나열하지 않고 다음 경험을 연결하는 기반으로 제시한다.

  `가족 프로필·보유 재료 확인 → 메뉴 추천 → 조리 중 대화 → 식사 기록 초안 → 구성원별 섭취량 확인 → 영양 분석 → 다음 메뉴 제안`

- 최종 추진 방향은 **식재료를 관리하는 AI에서 가족의 더 나은 식사 선택을 지원하는 AI로 확장**하는 것으로 정리했다.

## 2. 식생활 관리를 어렵게 만드는 네 가지 장벽 정리

식생활 관리가 어려운 이유를 다음 네 가지로 정리했다.

| 구분 | 의미 |
|---|---|
| 식욕·기호 조절 | 건강 목표를 알고 있어도 당장의 식욕과 취향이 식사 선택에 더 크게 작용함 |
| 식사 준비 부담 | 매 끼니 메뉴를 고르고 재료와 조리 시간을 고려하는 과정 자체가 부담임 |
| 관리 기준의 불확실성 | 현재 먹는 방식과 관리 방법이 적절한지 사용자가 스스로 판단하기 어려움 |
| 개인별 정보 부족 | 일반적인 건강 정보는 많지만 개인과 가족의 상황에 맞는 정보는 부족함 |

- 특히 `관리 기준의 불확실성`은 단순히 정보가 부족하다는 의미가 아니라, **현재의 식사 선택과 관리 방식이 맞는지 확신하기 어렵다**는 문제로 설명한다.
- `시간·선택 부담`처럼 의미가 즉시 드러나지 않는 표현은 피하고, 메뉴 결정과 식사 준비 과정에서 어떤 부담이 발생하는지 구체적으로 작성한다.

## 3. 기존 앱 중심 식생활 관리의 한계 구체화

기존 식단 관리 앱의 핵심 한계는 정보의 부족보다 **실천 과정의 부담이 계속 사용자에게 남아 있다는 점**으로 정리했다.

- 식사 전: 사용자가 메뉴와 재료를 직접 결정해야 함
- 식사 후: 섭취 내용을 반복해서 직접 기록해야 함
- 기록 이후: 현재 식사가 적절한지 사용자가 스스로 판단해야 함
- 가족 식사: 하나의 식사를 함께 먹더라도 구성원별 상황을 각각 관리해야 함

따라서 우리 서비스는 단순히 영양 정보를 더 많이 제공하는 것이 아니라, **식사 전·중·후로 단절된 관리 과정을 하나의 흐름으로 연결하는 것**을 목표로 한다.

## 4. 삼성 유사 서비스 대비 차별화 방향

삼성의 서비스는 개인 사용자 기준으로 보면 재료 관리, 레시피 추천, 영양 관리 등 우리 서비스와 유사하거나 더 발전된 기능을 제공할 가능성이 있다. 따라서 개별 기능의 개수보다 **가족이 실제로 함께 식사하는 방식**을 반영하는 구조를 차별점으로 삼는다.

### 공동 식사를 한 번의 흐름으로 기록

- 가족 구성원 여러 명이 같은 저녁을 먹었다면 식사를 한 번만 기록한다.
- 식사에 참여한 구성원과 각자의 실제 섭취량을 확인한다.
- 한 번의 기록으로 참여 구성원 모두의 섭취 기록과 영양 상태를 각각 업데이트한다.
- 구성원별 프로필에서 동일한 식사를 반복 입력해야 하는 개인 중심 관리 방식과 구분한다.

### 가족 공용 식사와 개인별 영양 목표를 함께 반영

- 하나의 가족 재고와 공통 메뉴를 기준으로 식사를 준비한다.
- 동시에 구성원별 건강 목표, 알레르기, 선호, 최근 섭취 이력을 반영한다.
- 가족에게 공통으로 적합한 메뉴와 구성원별 조정 사항을 하나의 서비스 흐름에서 제안한다.

> 핵심 차별점: 개인별 프로필을 단순히 여러 개 제공하는 것이 아니라, **가족이 함께 준비하고 먹은 한 끼를 기준으로 여러 구성원의 영양 관리를 동시에 연결하는 것**

## 5. DCX 분석 결과의 활용 범위 정리

현재 확보한 DCX 분석 결과만으로 최종 산출문서에 작성할 수 있는 범위와, 담당자에게 추가로 받아야 할 근거를 구분했다.

### 현재 자료로 작성 가능한 내용

- 분석 목적: 식재료 관리, 메뉴 선정, 가족별 영양 관리와 식사 기록 과정에서 나타나는 고객 고민 탐색
- 수집 범위: 네이버 블로그·카페·지식iN의 제목과 요약, 10개 탐색 영역 및 검색어 250개
- 분석 규모: 74,161건 수집 후 전처리를 거쳐 61,130건을 최종 분석 대상으로 사용
- 주제 도출: HDBSCAN 표본에서 40개 세부 군집을 발견하고 의미가 가까운 항목을 26개 주제로 통합
- 주제 할당 결과: 34,492건 할당, 26,638건 미할당
- 가족 영양 관리와 관련된 주요 주제 및 고민 후보를 활용한 타깃 선정 근거
- 메인 타깃 정의, 대표 페르소나, 고객 문제와 서비스 기능의 연결 가설

### 해석 기준

- 기회점수는 군집별 언급 비중과 감성 점수를 활용한 **상대적 탐색 지표**이며, 설문에서 측정한 고객 중요도·만족도나 실제 고객 비율로 해석하지 않는다.
- 메인 타깃은 분석 알고리즘이 직접 산출한 하나의 고객 군집이 아니라, 여러 식생활 주제와 서비스 사용 맥락을 종합해 설정한 **기획 타깃**으로 명시한다.
- 대표 페르소나의 이름·나이·가족 구성은 실제 게시글 작성자의 속성이 아니라 타깃을 구체화하기 위한 설정임을 밝힌다.
- 조리 중 대화를 활용한 기록 기능은 DCX 분석에서 직접 수요가 검증된 기능이 아니라, 관찰된 문제를 해결하기 위한 서비스 적용 가설로 구분한다.

### DCX 분석 담당자에게 추가로 받을 내용

- 최종 군집별 문서 수, 비중, 핵심 키워드와 군집명 전체표
- 핵심 군집을 대표하는 실제 게시글 사례 또는 비식별화된 대표 문장
- 문의성·후기성·일반 정보성 문서의 구분 기준과 각 유형별 분석 결과
- 전처리, 임베딩, 표본 추출, HDBSCAN 설정 및 군집 통합 기준
- 30~40대 주부를 메인 타깃으로 연결할 수 있는 직접적인 데이터 근거의 유무
- 최종 산출문서에 사용할 수 있는 그래프·표와 각 지표의 정확한 산식
- 분석의 한계와 결과를 해석할 때 주의해야 할 사항

## 6. 오늘 정리된 서비스 방향

- 서비스의 중심은 식재료 관리가 아니라 **가족의 식사 준비와 개인별 영양 관리를 연결하는 것**이다.
- 조리 중 대화는 단순한 레시피 질의응답이 아니라 실제 사용 재료와 조리 방식을 파악하는 기록 수단으로 활용한다.
- 식후에는 음식과 재료를 다시 입력하게 하지 않고, 구성원별 실제 섭취량만 간단히 확인한다.
- 경쟁 서비스와의 차별화는 단일 기능보다 **공동 조리·공동 식사·개인별 기록이 하나로 이어지는 경험**을 중심으로 설명한다.
- 메인 타깃은 가족 식사와 건강 관리를 주도하면서 구성원별 조건을 한 끼에 함께 반영해야 하는 사람으로 정의하되, DCX 결과만으로 특정 연령·성별의 대표성이 입증됐다고 표현하지 않는다.

## 추가 확인이 필요한 사항

- 삼성 서비스가 한 번의 공동 식사 기록으로 여러 가족 프로필을 동시에 업데이트할 수 있는지 공식 자료 또는 실제 사용 흐름으로 검증
- 추진배경에 사용한 통계 수치의 원문, 조사 대상, 기준 연도 재확인
- DCX 담당자의 추가 자료를 받은 뒤 핵심 군집, 고객 발화, 타깃 선정 근거 및 시각자료 보완
- DCX 분석 결과와 30~40대 주부 타깃 사이의 연결이 데이터 근거인지 기획 판단인지 최종 문서에서 명확히 구분
