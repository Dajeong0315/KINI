## 무엇을 기록하나요?

그날 해결한 문제와 담당 범위, 시도한 방법과 선택 이유, 결과와 다음 과제를 기록합니다. AI·비전·음성·추천·API·데이터 등 기술 작업은 가능하면 **변경 전후의 지표와 측정 조건**을 함께 남겨 주세요. 측정하지 못한 날에는 억지로 숫자를 만들지 말고 `미측정`과 이유를 적습니다.

- **성능:** 지표의 정확한 이름과 단위, 변경 전후 값, 평가 데이터와 건수, 측정 방법을 씁니다. 예를 들어 정확도와 mAP는 서로 다른 지표입니다.
- **실험:** 바꾼 모델·코드·하이퍼파라미터, 기존 값과 탐색 범위·간격, 시도 횟수, 최종 설정과 선택 이유를 남깁니다. 시도한 모든 값을 알 수 없으면 확인된 범위만 기록합니다.
- **속도:** 전체 응답 시간인지 STT·모델 추론·TTS 등 일부 구간인지 구분하고, 반복 횟수와 중앙값·평균·p95 등 집계 방법, 장비와 모델을 씁니다.
- **비교 조건:** 같은 데이터·환경·측정 방법으로 비교했는지 적습니다. 조건이 다르면 직접 개선 효과로 단정하지 않습니다. 실패한 시도와 부작용도 남깁니다.
- **근거:** 테스트 명령, 평가 스크립트, 실험 로그, 커밋이나 PR을 연결하고 실제 사용자 검증과 합성·모의 테스트를 구분합니다. 민감 데이터는 올리지 않습니다.

수치를 인용할 때 정확도 `85% → 91%`는 **6%p 증가**입니다. 시간 `10초 → 3초`는 **7초 감소, 70% 단축**입니다. 이 숫자는 작성 방법을 보여주는 가상 예시입니다.

## 작성 원칙

- 본인이 실제 수행한 일과 AI·팀원의 도움을 구분합니다.
- 계획·진행 중·완료와 실제로 테스트한 범위를 정확히 표시합니다.
- API 키, 개인정보, 원본 음성·대화, 로컬 DB 등 민감 자료는 기록하지 않습니다.
- 각자 브랜치에서 작성하고 팀의 PR 절차에 따라 공유합니다.
