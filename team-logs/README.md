# 팀 작업 기록

날짜별 폴더 안에 팀원 각자의 기록과 **팀 전체 성과 기록**을 함께 둡니다. 개인 파일은 본인이 그날 수행한 작업과 판단을, 팀 전체 파일은 팀이 공유·검증할 성능 결과와 통합 상태를 기록합니다.

```text
team-logs/
├── README.md
├── 새_날짜_만들기.py
├── templates/
│   ├── 개인_템플릿.md
│   └── 팀_전체_템플릿.md
├── 2026-11-25/
│   ├── 전다정.md
│   ├── 김진아.md
│   ├── 조민준.md
│   ├── 김재웅.md
│   ├── 이원준.md
│   └── 팀 전체.md
├── 2026-11-24/
│   └── 전다정.md
└── ...
```

## 매일 기록하는 방법

1. 저장소에서 `python team-logs/새_날짜_만들기.py`를 실행하면 한국 시간 기준 오늘의 폴더와 파일 6개가 생성됩니다. 다른 날짜는 `python team-logs/새_날짜_만들기.py 2026-11-26`처럼 지정합니다. 스크립트는 수동 실행하며 기존 파일은 덮어쓰지 않습니다. 기본적으로 평일 날짜만 생성하고 주말에는 생성하지 않습니다.
2. 본인 파일에 그날의 작업, 판단, 실험, 결과와 한계를 기록합니다. 실험하지 않았다면 해당 항목에 `미측정` 또는 `해당 없음`을 적습니다.
3. 모든 팀원은 `팀 전체.md`를 함께 편집할 수 있습니다. 각자 브랜치에서 수정하고 PR로 합칠 때 같은 부분을 변경했으면 팀 기록이 모두 남도록 충돌을 해결합니다. 실제 GitHub 쓰기 권한은 저장소 설정을 따릅니다.
4. 개인 기록이나 실험 로그를 근거로 팀 전체 파일에 **공유할 최종 결과, 비교 조건, 검증 상태와 남은 한계**를 정리합니다. 단순 할 일만 나열하지 않고 아직 결과가 없으면 `진행 중`과 측정 계획을 적습니다.

## AI에게 하루 기록 요청하기

팀원은 프로젝트 작업 대화에서 **“오늘 하루 기록해줘”**라고 요청하면 됩니다. AI는 한국 시간 기준 오늘 날짜와 요청자의 이름을 확인하고, 대화와 Git·테스트 등 접근 가능한 근거를 검토해 해당 날짜의 **개인 파일과 `팀 전체.md`를 함께 만들거나 업데이트**합니다. 이름이 불명확하면 누군지 물어볼 수 있습니다. 저장소 소유자나 Git 사용자 이름만 보고 추측하지 않습니다.

개인 파일에는 본인의 기여와 시도·판단·시행착오를, 팀 전체 파일에는 팀이 공유할 수 있는 확인된 성능·검증·통합 결과를 남깁니다. 팀 전체 기록에 반영할 근거가 개인 작업뿐이라면 그 범위를 분명히 하며, 측정하지 않은 수치는 `미측정`으로 둡니다. 기존 기록은 보존하고 반복 요청에도 같은 내용을 중복하지 않습니다.

예: `오늘 하루 기록해줘` / `11월 25일 작업 기록해줘`

에이전트용 구체 절차는 저장소 루트의 [AGENTS.md](../AGENTS.md)에 있습니다. 이 방법은 해당 지침을 읽을 수 있는 프로젝트 에이전트에서 동작하며, 접근할 수 없는 다른 대화나 실험 결과까지 자동으로 확인할 수는 없습니다. 기본 날짜 생성기는 주말을 건너뛰지만, 사용자가 주말 기록을 명시적으로 요청하면 그 날짜에 기록할 수 있습니다.

## 수치와 실험 기록 기준

- **성능:** 지표의 정확한 이름과 단위, 변경 전후 값, 절대·상대 변화량을 남깁니다. 예를 들어 정확도 `85% → 91%`는 `6%p 증가`, 응답시간 `10초 → 3초`는 `7초 감소·70% 단축`입니다. 이 숫자는 가상 예시입니다. 정확도, mAP, 재현율 등 서로 다른 지표를 혼용하지 않습니다.
- **측정 조건:** 모델·코드 버전, 데이터 출처·분할·표본 수, 장비, 측정 구간, 반복 횟수와 평균·중앙값·p95 등 집계 방법을 기록합니다. 이전과 이후의 조건이 달랐다면 차이를 밝혀 직접 비교를 피합니다.
- **시행착오:** 하이퍼파라미터 이름, 변경 전 값, 탐색 범위와 간격, 총 시도 횟수, 최종 값, 실패와 부작용을 기록합니다. 둘 이상을 함께 바꿨다면 개별 원인을 단정하지 않습니다.
- **검증 수준:** 실제 연동과 fake/mock, 합성 평가, 실제 사용자 평가를 구분합니다. 측정하지 않은 성능이나 품질을 추정해 채우지 않습니다.
- **근거와 재현:** 실험 스크립트, 명령, 로그, 데이터 버전, 관련 커밋·PR 및 담당·검토자를 연결합니다. 미완료 실험은 잠정 결과로 표시합니다.

## 작성과 공유 원칙

- 본인 작업과 AI·팀원의 기여를 구분하고, 팀 성과는 참여자와 역할을 명시합니다.
- API 키, 개인정보, 원본 음성·대화, 로컬 DB 등 민감 자료는 올리지 않습니다.
- 기존 종합 회고는 2026-11-11부터 2026-11-25까지 평일 날짜별 `전다정.md`로 나누었습니다. 이전에 확인된 주말 날짜의 대화 기록은 해당 날짜를 명시해 다음 평일 파일에 참고자료로 보존했습니다. 확인되지 않은 내용은 미확인으로 표시하며, 다른 팀원의 과거 기록은 각자 추가합니다. 포트폴리오 사례와 출처는 [11월 25일 개인 기록](2026-11-25/전다정.md)에 보존했습니다.
